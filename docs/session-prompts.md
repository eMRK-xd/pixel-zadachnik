# Промпты для отдельных сессий

Каждый промпт вставляется в новый чат Claude Code, открытый в папке проекта. Идеи взяты из задач в колонке «Прочее».

**Важно:** почти все сессии правят один и тот же `web/index.html`. Если запускать их одновременно, они будут мешать друг другу. Варианты:
- по одной сессии за раз;
- каждую сессию в своей ветке или рабочей копии (в приложении Claude: новая сессия с отдельным worktree) и сливать по очереди.

## 1. Полировка интерфейса

```
Прочитай CLAUDE.md. Задача — полировка интерфейса задачника:
1) Плавное раскрытие подзадач: сейчас карточка раскрывается мгновенно. Сделай мягкую анимацию раскрытия и сворачивания (высота + появление строк), в пиксельном стиле, без тормозов на телефоне.
2) Глаза у скинов «скачут»: зрачок прыгает между позициями. Сделай плавное следование, как у глаза на карточке «А как же ваши задачи?» в web/bye.js (цель + плавное приближение к ней каждый кадр). Проверь на всех скинах, включая двухглазые.
3) Настройки раскрываются так же красиво, как панель дейлика (анимации unfold/rise в index.html).
4) В раскрытой карточке задачи показывать, с какого устройства она добавлена: ПК, телефон или сайт (и через MCP/Клода). Сохранять это в задаче при создании (у старых задач — не показывать).
Сначала покажи макетом в браузере (web/_*.html или прямо на странице через ?mobile), дождись моего выбора, потом переноси. Коммит и релиз — только после моего «да».
```

## 3. Плагины: дейлик, отчёт, таймер, записки

```
Прочитай CLAUDE.md и docs/MODS.md. Система модов уже есть (web/mods-host.js, первый мод — web/mods/vinyl). Задачи:
1) Вынести дейлик и кнопку отчёта в отключаемые плагины (настройки → моды), не ломая текущее поведение по умолчанию. Если это встроенные части приложения, а не песочница, придумай для них «встроенные модули», которые включаются и выключаются так же.
2) Плагин-таймер (скорее секундомер) прямо на задаче: запустил на карточке — тикает, время копится в задаче и синкается. Для этого модам нужно новое место встраивания — карточка задачи. Расширь API аккуратно, с разрешениями.
3) Плагин «записки», которые синхронизируются с Obsidian: на ПК — через папку хранилища Obsidian (выбор папки, чтение и запись .md через Rust-команды, только внутри выбранной папки). На телефоне — хотя бы просмотр через синк.
Сначала предложи план и макеты, потом делай по одному плагину. Коммит и релиз — только после моего «да».
```

```
Прочитай CLAUDE.md и docs/HANDOFF.md (разделы про данные и синк). Хочу менять вкладки и делать мастер-вкладки (проекты): «работа», «жизнь», «приложение» и т.п., а внутри каждой — свои подвкладки (сейчас колонки задач зашиты в COLS в index.html). Нужно:

Сначала опиши план миграции и покажи макет интерфейса. Данные пользователя не потерять ни при каком сценарии: перед миграцией делать резервную копию. Коммит и релиз — только после моего «да».

```
Прочитай CLAUDE.md. Добавь вкладку «аналитика» справа от «календаря»: график-ломаная (сделанные задачи по дням) и гистограммы по колонкам за неделю и месяц, переключатель неделя/месяц. Ещё одна кнопка — «аналитика мышления»: собирает задачи, заметки дейлика и цели в промпт для Клода, который разберёт, как я мыслю и планирую (какие темы повторяются, где распыляюсь, что откладываю), и копирует его. Данные: S.tasks и S.archive (doneAt, added, col). Графики рисуй сам, в пиксельном стиле, без внешних библиотек. Сначала макет, потом перенос. Коммит и релиз — только после моего «да».

## 6. Виджет Android

```
Прочитай CLAUDE.md. Сделай виджет для домашнего экрана Android: глаз выбранного скина и надпись «N задач на сегодня» / «всё сделано»; зрачок узкий, когда задач много, широкий, когда мало (как dil() в index.html). Виджет нативный (AppWidgetProvider на Kotlin/Java), Android-проект генерируется в GitHub Actions (.github/workflows/android.yml, папка mobile/), поэтому файлы виджета нужно класть в репозиторий и подкладывать в сгенерированный проект в workflow. Данные из приложения: записывать в SharedPreferences (например, через маленький свой Capacitor-плагин) и просить виджет обновиться при каждом изменении задач. Картинки глаза рисовать в коде или генерировать скриптом. Гироскопа на виджете не будет — Android это не позволяет. Проверить на телефоне могу только я — дай понятную инструкцию, что проверить. Коммит и релиз — только после моего «да».
```

Обе вещи опираются на дополнительные окна Tauri — сделай общую основу. Проверяй в собранном exe (npm run build). Коммит и релиз — только после моего «да».

## Банк идей (на потом)

Короткие заметки о том, что хочется переделать, но пока не горит.

- **Задержка при раскрытии карточки на слабом телефоне.** Замерено на слабом телефоне (MT6769, 90 Гц) через adb и отладку WebView:
  - сама анимация идёт почти 60 кадров/с;
  - но первое касание экрана после запуска стоит ~130–150 мс на видеокарте;
  - первое открытие каждой карточки — ещё 1–2 кадра на отрисовку нового текста.

  Уже сделано: звук прогревается при первом касании; карточка открывается сразу (раньше ждала 230 мс, чтобы отличить двойной тап, теперь двойной тап ловится сам); отклик на касание в тот же кадр; настройка «анимации: плавно / быстро / выкл». Невидимая прорисовка карточки при старте не помогла. Идеи на потом:
  - держать подзадачи в DOM всегда свёрнутыми, чтобы раскрытие ничего не создавало;
  - проверить, не дешевле ли всё это с отключённым аппаратным ускорением отдельных слоёв.

  Как мерить: `docs/HANDOFF.md` → раздел про проверку на телефоне (adb, `chrome://inspect`).
